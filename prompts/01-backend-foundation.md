# Prompt 01 - Backend foundation (run first, alone)

Read prompts/hcm/00-SPEC.md completely, then knowledge.md and docs/ARCHITECTURE.md. You are converting the existing boilerplate server into the HCM Lite foundation. Change server/ and docs only. Follow section 0 of the spec.

## Steps
1. Dependencies: in server/ run npm install pdfkit csv-parse. Nothing else.
2. Remove what the spec lists as removed (items module, uid lookup routes, avatar and Cloudinary code, Google, Facebook, public register, email verification at sign-up and its model purpose, find-user). Keep forgot-password OTP, the AI key pool, the AI admin routes, the Conversation model, rate limiters and the error handler. Remove their env variables from env.js and .env.example. The server must still boot.
3. Utilities: utils/dates.js and utils/clock.js exactly as listed in spec section 1, utils/money.js (round2), utils/haversine.js (distanceMeters(lat1,lng1,lat2,lng2)), utils/temporaryPassword.js (crypto, 10 characters, letters and digits, at least one of each).
4. Models and services for: Settings, Department, Designation, LeaveType, Holiday, Employee, AuditLog (immutable as described), Notification, Announcement, AiLog. Update User (roles admin|hr|employee, employeeId, isActive, mustChangePassword; remove age, gender, avatar, googleId, uid). Services: settingsService (get with a short in-memory cache that is cleared on update), calendarService (holidaySet(from,to), a helper that returns settings + holidaySet), auditService.log, notificationService.notify and notifyMany.
5. Auth changes: login rejects inactive users; login and /auth/me return { user, employee summary, mustChangePassword }; POST /auth/change-password; protect middleware loads role and employeeId and enforces mustChangePassword exactly as in spec section 2; restrictTo(...roles).
6. First-run setup: GET /setup/status and POST /setup. The second call must return 409 even when two requests arrive at the same time (use an atomic findOneAndUpdate on Settings.setupComplete). Setup creates the settings document, seeds the four leave types, creates the Admin user (mustChangePassword false) and writes the audit entry. At server start, if no admin exists and ADMIN_EMAIL and ADMIN_PASSWORD are set, do the same with COMPANY_NAME (default "My Company"). Add AI_API_KEY and AI_PROVIDER to env.js and the key seeding code (seed only when no AiKey exists).
7. Setup data endpoints with zod validation, audit logging and 409 on delete-in-use: settings (validate HH:mm, weekendDays 0..6 unique, lat/lng ranges, radius 10..5000, graceMinutes 0..120, halfDayHours 1..12, timezone must be a valid IANA zone), departments, designations, leave types (quota null or whole number >= 0, code slug), holidays (ISO date).
8. Users (admin): POST /users/hr creates the user and the employee record in one go (employee code auto-generated EMP-0001, EMP-0002, ... with an atomic counter; user.mustChangePassword true; returns the temporary password once), GET /users, PATCH /users/:id/active (deactivating also clears refresh tokens), POST /users/:id/reset-password (sets mustChangePassword true, clears sessions, audit without the password). The admin account itself cannot be deactivated or reset here.
9. Announcements, notifications and audit routes as in spec section 5. The audit route is read-only.
10. Register everything in routes/index.js with one line per router. Update the env validation and .env.example (COMPANY_NAME, AI_API_KEY, AI_PROVIDER; keep TRUST_PROXY_HOPS).
11. Unit tests (server/test/*.test.js, node:test, script npm test): dates helpers (timezone conversion for Asia/Karachi both directions, month bounds, working days with a holiday and weekend settings, weekday), haversine (known distance between two points about 150 m apart), round2, temporary password policy.

## Self-check (do all of it yourself, no questions)
Start the server on database hcm_test and run a temporary script that proves, with real HTTP calls: setup status false, setup 201, second setup 409 (also two parallel calls give one 201 and one 409), login works, wrong password 401, env bootstrap creates the admin on an empty database, admin creates an HR user and gets a temporary password, HR login returns mustChangePassword true, HR calling any other route gets 403 PASSWORD_CHANGE_REQUIRED, change-password works then the same route works, HR cannot PATCH settings (403), admin can, settings validation errors (bad time, bad zone), department/designation/leave-type/holiday CRUD with delete-in-use 409, deactivated user cannot log in, reset password returns a new temporary password and forces a change, announcements post and list, notifications appear for the other users and mark-read works, audit log lists the actions and contains no password or hash text (search the JSON), there is no way to update or delete an audit entry (try the model methods in the script and expect an error). Also run npm test. Drop hcm_test, delete .tmp, update docs/ARCHITECTURE.md and knowledge.md (new structure, how to remove or add modules). Report.
