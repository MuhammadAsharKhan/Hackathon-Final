# Prompt 02 - Backend people: employees, attendance, leave (run after 01)

Read prompts/hcm/00-SPEC.md completely, then knowledge.md and the existing server structure from prompt 01. Change server/ and docs only. Follow section 0 of the spec. Add routers with one line each in routes/index.js (another prompt may add lines at the same time, never rewrite the file).

## Steps
1. Employees (spec sections 3, 5): services/employeeService.js and controllers/routes for register (creates the User with role employee, mustChangePassword true, temporary password returned once, welcome notification, audit), list with server-side search and filters and paging, get, 360 view, update details, salary update (with the HR and Admin rules from spec section 2, audit before/after), PATCH /me/profile (phone, address only), CSV import (dry run and real, using csv-parse with multer memory upload limited to 1 MB and 2000 rows), export and template. Salary fields are hidden from responses to employees except their own record. Employee 360 uses the services below.
2. Attendance: services/attendanceCalc.js with the pure function buildEmployeeDays exactly as spec 4.1, plus pure helpers computeCheckInStatus(now, settings) and computeCheckOutStatus(record, now, settings). services/attendanceService.js: today, check-in, check-out (spec 4.2 including the Haversine location rules), monthly calendar with summary (counts per status, hours worked, late count, attendance rate), board for one date (all active employees, derived statuses, filters, paging), employee month view. Corrections (spec 4.3) with notifications and audit.
3. Leave: services/leaveService.js (working days calculation using the calendar helpers, balance per type, preview, apply, cancel, decision) following spec 4.4 exactly, including the HR and Admin decision rules, notifications and audit. Seed nothing.
4. Wire a helper that other modules reuse: getEmployeeDaysForRange(employeeIds, from, to) which loads settings, holidays, attendance records and approved leaves in a fixed number of queries and returns buildEmployeeDays for each employee. Payroll and dashboards will import it, so keep its signature stable and document it in docs/ARCHITECTURE.md.
5. Unit tests (node:test, pure functions only): buildEmployeeDays with a table of cases (before join, after exit, future day, weekend, holiday, approved leave, absent, present, late at 09:16, NOT late at 09:15, half day at 4h59m vs 5h00m, missing checkout yesterday vs today, record on a weekend), timezone cases (check-in at 03:50 UTC is 08:50 in Karachi so present; 04:16 UTC is 09:16 so late; a check-in at 20:00 UTC belongs to the NEXT local date), leave working-day counting across a weekend and a holiday, overlap detection, balance maths, geofence acceptance and rejection.
