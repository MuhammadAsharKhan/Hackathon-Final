# Prompt 06 - Frontend people: employees, attendance, leave (run after 05)

Read prompts/hcm/00-SPEC.md completely (sections 4.1 to 4.4, 5, 7), then knowledge.md, theme.md, docs/ARCHITECTURE.md and the shared components from prompt 05. Change client/ and docs only. Follow section 0 of the spec. Match the server routes if they exist (read routes and controllers), otherwise build to the spec and list mismatches under Known issues. Reuse components; pages only compose.

## Steps
1. Employees (/employees; HR manages, Admin views): DataTable with search, department, designation and status filters, paging, status badges, row click to the Employee 360 page. HR actions: Register employee modal (all fields from the spec, designation list filtered by department, join date, gender, basic salary with live gross preview using hra 40 percent and medical 10 percent) that shows the temporary password once with a copy button; Import CSV modal (download template, choose file, "Check file" runs the dry run and shows a table of row, field and reason, "Import" enabled only when the dry run has zero errors, after import show the created logins with a "Download CSV of passwords" button); Export CSV button (fetch as blob with the auth header and save the file).
2. Employee 360 (/employees/:id): header (name, code, department, designation, status badge), tabs: Profile (details, edit modal for HR including exit date), Attendance (month picker, summary cards, the day list), Leave (balances cards, recent requests), Payroll (salary structure card with basic, HRA, medical, gross for HR and Admin only, edit salary modal for HR, and the list of finalized payslips with PDF buttons). Employee role opening their own record sees the same page without salary editing; any 403 shows a clear message.
3. My attendance (/me/attendance for HR and Employee): a CheckInPanel component (today's status, Check in and Check out buttons that disable correctly, shows server time stamps in company timezone, hours so far, friendly messages for 409 and 422) and a month calendar grid (7 columns, weeks start Monday, each day colored by status with a legend, off days muted, future days empty, tooltip or tap detail with check-in and check-out times) plus summary cards (present, late, half days, absent, on leave, attendance rate, hours). Month picker. Clicking a past day opens the Request correction modal (date fixed, check-in and check-out time inputs, reason textarea, validation) and a list "My correction requests" with status badges.
4. Attendance board (/attendance for HR and Admin): date picker (default today), department filter, search, status filter, DataTable of every active employee with derived status badge, check-in and check-out times, hours; summary strip (present, late, absent, on leave, half day). Tab "Corrections": inbox of pending requests (HR) with Approve and Reject (comment modal, reject requires comment), shows requested vs current times; Admin sees the list and can decide only HR-role requests (hide buttons otherwise; the server enforces anyway). HR cannot see decision buttons on their own requests.
5. My leave (/me/leave): balance cards per leave type (quota, used, pending, remaining; unlimited shows "Unlimited"); Apply form (type select, start and end date, reason, live preview line from POST /leave/preview showing working days and remaining balance or the exact problem, submit disabled when invalid); SmartLeaveBox above the form (textarea "Describe your leave in plain words", button "Fill the form for me", calls POST /ai/smart-leave, on success fills the form fields and shows a clear "AI-generated, please check the dates and confirm" note with the computed days, on fallback shows "Could not understand, please fill the form"; it never submits by itself); History DataTable (type, dates, days, status, decision comment, Cancel button when allowed with confirm).
6. Leave requests (/leave/requests for HR and Admin): tabs Pending, Approved, Rejected, All with filters (employee search, date range), DataTable with employee, type, dates, days, reason; Approve and Reject buttons open a comment modal (comment required for reject); HR cannot decide their own requests, Admin can decide HR requests only, buttons hidden otherwise with a small explanation text.
7. Make all API files (employees.api.js, attendance.api.js, leave.api.js) return unwrapped data and surface server messages (including 409 and 422 text) to the user in toasts or inline errors. CSV downloads and later PDF downloads use axios responseType blob.
