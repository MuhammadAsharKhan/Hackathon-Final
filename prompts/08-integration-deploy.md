# Prompt 08 - Integration, RBAC proof, README and deploy readiness (run after 01 to 07)

Read prompts/hcm/00-SPEC.md completely, then knowledge.md, docs/ARCHITECTURE.md and the README. You have two jobs: prove the whole product works the way judges will use it, and make the repository ready for submission. Follow section 0 of the spec. Fix every bug you find (minimal changes), in server/ or client/.

## Part 1: automated demo run (kept in the repo)
Create scripts/demo-check.mjs (plain Node 18 fetch, no dependencies) with npm script "demo:check" in the root package.json. It takes BASE_URL (default http://localhost:5000/api). It REFUSES to run when GET /setup/status says setup is already complete (print why and exit 1), because the hosted app must stay empty for the judges. It plays the official 5-minute demo and prints a PASS/FAIL line per step, exits 1 on any failure:
1. First-run setup with company name and admin. Admin sets office hours, location and radius, creates a department, a designation, one holiday, and an HR login (temporary password returned).
2. HR signs in (forced password change), registers three employees (one joins mid-month). One employee signs in, changes the password, checks in; second check-in is 409; checks out.
3. Employee asks smart leave for "next Monday and Tuesday off for my sister's wedding" (skip with a clear SKIPPED line if AI is not configured), then applies with preview; overlap and over-balance attempts give 422; HR approves; balance drops; notification exists.
4. HR dashboard KPIs equal values computed independently inside the script from the same records; Summarize returns 3 to 5 bullets; the assistant answers "Who is on leave today?" and "How many active employees are in <department>?" using tools and the numbers match the dashboard; an employee asking for a colleague's salary gets a reply that does not contain the salary digits.
5. HR creates the payroll draft for the current month, Admin finalizes, HR cannot edit afterwards (409), employee downloads the payslip PDF (starts with %PDF), employee cannot download a colleague's.
6. Admin audit log contains setup, HR creation, employee registration, leave decision, payroll create and finalize with actors; the audit route has no write methods (405 or 404 for PATCH and DELETE).

Create scripts/rbac-matrix.mjs the same way (own file, npm script "rbac:check"): a table of every route in spec section 5 against admin, hr, employee and anonymous with the expected status class (2xx or 401 or 403), plus object-level checks (employee reading another employee's record, payslip, attendance, leave request, correction; HR deciding own request; Admin finalizing twice). It must print the matrix and exit 1 on any mismatch. Also confirm no response anywhere includes passwordHash, refresh token fields or provider keys.

Create scripts/reset-db.js (npm script "db:reset") that drops the database named in MONGODB_URI only when run with the exact database name as an argument (node scripts/reset-db.js hcm-lite); otherwise it prints usage and exits.

Run everything on database hcm_test with a freshly started server (also once with NODE_ENV=production to prove production behavior: secure cookie flags, no stack traces). Run npm test in server/. Fix failures and re-run until green. Drop hcm_test afterwards.

## Part 3: README and submission files
Write README.md (replace the boilerplate one) with: one paragraph on what HCM Lite is; stack; architecture in a short diagram-free list; how to run locally in under 10 minutes (install, env, start, open, first-run setup, or ADMIN_EMAIL and ADMIN_PASSWORD env route); environment variable table for server and client; how to set the AI key (AI_API_KEY and AI_PROVIDER, or several keys in /admin/ai, explain rotation); how to deploy (frontend on Vercel with root directory client and the /api rewrite in client/vercel.json, backend on Railway with root directory server, start command npm start, MongoDB Atlas network access 0.0.0.0/0, the required variables, TRUST_PROXY_HOPS=2, health route for keep-alive); how to run the checks (npm test, demo:check, rbac:check); a table of the 25 functionalities with Done or Not done and the module name; a list of optional bonus items done or not done; known limitations and design decisions in plain words (company timezone, check-in allowed on off days, HR and Admin decision rules, no photo stored).
