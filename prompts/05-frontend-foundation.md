# Prompt 05 - Frontend foundation (can run in parallel with the backend prompts)

Read prompts/hcm/00-SPEC.md completely (sections 2, 5, 7), then knowledge.md, theme.md and docs/ARCHITECTURE.md. Change client/ and docs only. Follow section 0 of the spec. If server route files already exist, read them and match them exactly; for anything missing build against the spec contract and list it under Known issues. Existing components in components/ui are reused first (component-first rule); do not hand-write controls in pages.

## Steps
1. Dependencies: npm install recharts in client/. Nothing else.
2. Theme: keep the white background and neutral tokens from theme.md; change only the primary accent token to a deep teal (#0f766e) and its hover shade, and add a soft tinted surface token for stat cards. Update theme.md. No emoji, no gradients.
3. Remove pages and code for removed features: Register, VerifyEmail, FindUser, AiBuddy, items Dashboard, Google button, CompleteProfileModal, avatar upload, UID copy. Keep Login, forgot-password modal, Tabs, Modal, ConfirmDialog, Pagination, OtpInput, Spinner, Button, Input, Select, Textarea, Card, Badge, EmptyState, PageHeader and the admin AI keys page (rename the route /admin/ai, menu label "AI keys").
4. New shared components (components/ui and components/data): DataTable (columns config, loading skeleton rows, empty state, error state with retry, optional pagination footer), StatCard, StatusBadge (maps attendance, leave and payroll statuses to colors and labels), FormField wrapper if missing, DateInput and MonthInput (native inputs styled), ConfirmDialog usage helper, CopyButton (with clipboard fallback), FilterBar (department select, date range, search with 400 ms debounce), PageSection, ChartCard (title + recharts container with empty state).
5. App shell: components/layout/AppShell with a sidebar (collapsible drawer under md), top bar (page title, notification bell with unread count polled every 30 s and a dropdown list with mark-all-read, user menu with Change password and Sign out). Menus per role exactly as spec section 7, defined in one config file (config/menus.js) with role lists. Active link styling, keyboard accessible.
6. Routing and guards: ProtectedRoute with roles, GuestRoute, a SetupGate that calls GET /setup/status once at start: when setup is incomplete redirect everything to /setup; when complete /setup redirects to /login. A forced /change-password route: when /auth/me says mustChangePassword (or any API answers PASSWORD_CHANGE_REQUIRED) redirect there and block other routes until done. Role based default landing at /dashboard. Unknown routes show NotFound.
7. Pages in this prompt: Setup (company name, admin name, email, password and confirm; success signs in and goes to /admin/organization), Login (no register link, forgot password stays, shows a short note on first-run if setup is incomplete), ChangePassword (used for forced and voluntary change; password rules shown), Organization (Admin: Tabs Company (settings form including timezone select, office start time, grace, half-day hours, weekend day checkboxes, office latitude/longitude with a "Use my current location" button and radius, weekly hours), Departments, Designations, Leave types, Holidays - each a DataTable with add/edit modal and delete confirm showing the 409 message), AdminUsers (Admin: HR logins table with search, create HR modal (name, email, department, designation, join date, basic salary, gender, phone) that shows the temporary password ONCE in a modal with a copy button and a warning, activate/deactivate toggle with confirm, reset password with the same one-time display), Announcements (list newest first, post form for Admin and HR, delete for Admin or author), AuditLog (Admin: DataTable with filters actor, action, entity, date range, rows expandable to show before/after JSON in a readable block), MyProfile (/me/profile for HR and Employee: read-only details, edit phone and address, change password link).
8. API layer: src/api/*.api.js files for setup, auth, settings, organization, users, announcements, notifications, audit, profile. Interceptor behavior stays as in the boilerplate; add handling that maps 403 PASSWORD_CHANGE_REQUIRED to the redirect. Network failure and 429 show readable messages.
9. Use ScrollManager and the existing smooth scroll. Every data view has loading, empty and error states. Forms disable while submitting and show server field errors under the right input. Mobile first, works from 375 px.
