# Prompt 03 - Backend payroll and analytics (run after 01 and 02)

Read prompts/hcm/00-SPEC.md completely, then knowledge.md and docs/ARCHITECTURE.md. Reuse getEmployeeDaysForRange and buildEmployeeDays from prompt 02; never recompute attendance in a second way. Change server/ and docs only. Follow section 0 of the spec.

## Steps
1. services/payrollCalc.js (pure, no database): grossOf, annualTax, calculatePayslip({ employee, month, settings, holidaySet, days, today }) implementing spec 4.5 exactly and returning every Payslip number field. Unit tests with the worked example from the spec (must give 119545.45 net), plus: every tax slab boundary (600000, 1200000, 2400000, 3600000 and one rupee above each), a mid-month joiner, a mid-month leaver, a month with no absences (net = gross - tax), the current month (days after today never count as absent), and net never below zero.
2. services/payrollService.js, controllers and routes for runs and payslips exactly as spec section 5: create or recalculate the draft, list runs, run detail with payslips, finalize (Admin only, locks, notifications to employees, audit with totals), my payslips, payslip detail, payslip PDF. Use a MongoDB transaction-free approach: build all payslips first, then replace the draft's payslips in a bulk write, then set totals.
3. Payslip PDF with pdfkit (services/payslipPdf.js): company name, month, employee name, code, department, designation, an earnings table (basic, HRA, medical, gross, earned gross), a deductions table (absent, unpaid, half day, tax), the attendance counts, net pay in bold, and "Generated on <date>". Plain black on white, tidy alignment, no emoji. Stream with Content-Type application/pdf and a filename like payslip-EMP-0001-2026-10.pdf. Scope rules as in spec (employees only their own finalized payslips).
4. services/analyticsService.js with one exported function per metric from spec 4.6: headcountAt, headcount, attrition, attendanceSummary(range, departmentId) (counts per status, attendance rate, late %, absenteeism), attendanceTrend (daily rate), absenteeismByDepartment, topLateComers(limit), leaveSummary (days by type, utilization, who is on leave today), payrollCost (byMonth, byDepartment), averageSalary (byDepartment, byDesignation), headcountByDepartment, genderSplit, tenureBuckets (under 1 year, 1 to 3, over 3), pendingApprovals, personal metrics (hoursThisWeek, lateCount, lastPayslip). Efficient enough for a few thousand employee-days: use getEmployeeDaysForRange once per request.
5. services/dashboardService.js composes those into the three dashboard payloads from spec section 5 and controllers/routes for /dashboard/admin, /dashboard/hr, /dashboard/me with the from, to, departmentId filters. HR and Admin payloads must use the same analytics functions so the same filters give the same numbers. Add a department filter validation (unknown id -> 400).
6. Unit tests for the pure parts of analytics (headcountAt around join and exit dates, attrition formula, attendance rate formula, late %, tenure buckets).
